# F2.7–F2.16: Controller, JavaScript, Templates & Quality for Candlestick Chart

**Date:** 2026-03-16  
**Scope:** Presentation layer — REST + view endpoints, TradingView JS integration, Thymeleaf templates

---

## Summary

Completes the candlestick chart feature by adding the HTTP endpoints (F2.7–F2.8), external JavaScript chart rendering via TradingView Lightweight Charts v4 (F2.10–F2.11), new and updated Thymeleaf templates (F2.12–F2.13), and the corresponding unit tests (F2.9, F2.14–F2.16).

---

## Changes Made

### F2.7 — `GET /analysis/ticker/{id}/candles` (JSON endpoint)

Added to `AnalyzeTickerController`. Annotated `@ResponseBody` + `produces = APPLICATION_JSON_VALUE` so it coexists with the existing `@Controller` without needing a separate `@RestController`. Delegates directly to `ManageAnalyzeTickerUseCase.findCandlesByStockId(id)` and returns the `CandleChartDTO` built by the backend.

### F2.8 — `GET /analysis/ticker/{id}/chart` (Thymeleaf view endpoint)

Added to `AnalyzeTickerController`. Loads the `StockDataDTO` via `findStockDataById`, places it in the model under `ticker`, and resolves to the new `analysis/ticker-chart` template.

### F2.9 — Controller unit tests (4 new tests)

Added to `AnalyzeTickerControllerTest`:
- `getCandleChart_delegatesToUseCase_returnsCandleChartDTO` — verifies delegation + DTO content
- `getCandleChart_noCandles_returnsEmptyList` — edge case with empty series
- `getTickerChart_addsTickerToModel_returnsChartView` — view name + model attribute
- `getTickerChart_callsFindStockDataById_withCorrectId` — id routing correctness

### F2.10 — `candle-chart.js`

Renders a full TradingView Lightweight Charts v4 candlestick chart inside `#candle-chart`. SMA20/50/200 line series are computed client-side from raw close prices (avoids server-side time series; keeps SRP). Includes responsive resize handler and graceful error / empty-data states.

### F2.11 — `mini-chart.js`

Renders a compact, non-interactive thumbnail in `#mini-chart` showing the last 60 candles. No axes/crosshair/scroll are shown. Clicking the container navigates to `/analysis/ticker/{id}/chart`. All DOM event listeners are registered in the JS file — no inline handlers in HTML (SonarQube compliant).

### F2.12 — `ticker-chart.html`

New Thymeleaf template at `analysis/ticker-chart.html`:
- Header with ticker logo, name, back-to-detail button
- Colour-coded SMA/candle legend
- Full-height chart card with `#candle-chart` div and `data-ticker-id` data attribute
- Reference SMA scalar table below the chart
- TradingView CDN + `candle-chart.js` loaded at end of body

### F2.13 — Mini-chart in `ticker-detail.html`

Added a card between the evaluation row and the "Indicadores Técnicos" row. Contains:
- Card header with "Gráfico de Velas" title and "Ver completo" link button
- `#mini-chart` div with `th:attr="data-ticker-id=${ticker.id}"` (no inline JS)
- TradingView CDN + `mini-chart.js` script tags injected before `</body>`

### F2.14–F2.16 — Tests & documentation

- Total test count: 634 (up from 630), 0 failures
- `AnalyzeTickerControllerTest`: 4 new tests for F2.7 and F2.8
- CodeQL: 0 alerts

## Technical Decisions

| Decision | Rationale |
|---|---|
| `@ResponseBody` on single method | Avoids full `@RestController` refactor; coexists cleanly with view methods |
| TradingView Lightweight Charts v4 via unpkg CDN | Apache 2.0, ~40 KB, zero dependencies, native candlestick + line support |
| SMA computed client-side in JS | Server returns scalar SMAs as reference; series built from raw closes (SRP, avoids server-side time-series computation) |
| `data-ticker-id` attribute for JS data binding | SonarQube-compliant; no inline JS or `th:onclick` |
| Last 60 candles in mini-chart | Sufficient to show trend; keeps thumbnail lightweight |
| Graceful empty-data / error states in JS | UX stability when no candles have been persisted yet |
