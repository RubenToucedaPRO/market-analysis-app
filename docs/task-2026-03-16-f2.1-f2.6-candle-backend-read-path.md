# F2.1–F2.6: Backend Read Path for Candlestick Chart Data

**Date:** 2026-03-16  
**Scope:** Application backend — domain port, infrastructure, application DTOs, mapper, use-case

---

## Summary

Implements the complete backend read path required to serve OHLCV candle data to a future candlestick chart view. No HTTP endpoints or frontend changes are included in this task.

---

## Changes Made

### F2.1 — `CandleHistoryRepository` (domain port out)

Added `findCandlesByTicker(String ticker)` to the output port interface with Javadoc. Keeps the port write+read and ensures the application layer can request persisted candles without knowing the persistence technology.

### F2.2 — `SqlCandleHistoryRepository` (infrastructure)

Implemented `findCandlesByTicker`: validates the ticker with Spring's `Assert.hasText`, delegates to `JpaCandleRepository.findByTickerOrderByDateTimeAsc` (already existing ordered query), and maps entities to domain objects via `CandleMapper.toDomain`. Includes `debug`-level observability logging consistent with the existing write methods.

### F2.3 — `CandleDTO` (application/dto)

New DTO representing a single OHLCV candlestick data point:
- `time` (`long`) — Unix epoch seconds (required by TradingView Lightweight Charts v4)
- `open`, `high`, `low`, `close` (`BigDecimal`)
- `volume` (`Long`)

### F2.4 — `CandleChartDTO` (application/dto)

New DTO wrapping the full chart payload:
- `ticker` (`String`)
- `candles` (`List<CandleDTO>`) — ordered ascending
- `sma20`, `sma50`, `sma200` (`BigDecimal`) — current scalar values from the persisted stock; nullable if insufficient data

### F2.5 — `ManageAnalyzeTickerUseCase` (domain port in)

Added `findCandlesByStockId(Long id)` to the inbound use-case port. Returns `CandleChartDTO`. Note: the import of `CandleChartDTO` (application layer) from the domain port is consistent with the pre-existing pattern where `StockDataDTO` is also imported from the domain port interface.

### F2.6 — `ManageAnalyzeStockService` (application use case)

Implemented `findCandlesByStockId`:
1. Loads the `Stock` by id (throws `StockDataNotFoundException` if absent)
2. Reads candles via `CandleHistoryRepository.findCandlesByTicker(ticker)`
3. Delegates mapping to `CandleDTOMapper.toChartDTO(stock, candles)` — SRP-compliant

### `CandleDTOMapper` (application/mapper)

New dedicated mapper component with two methods:
- `toDTO(Candle)` — maps a single domain candle to `CandleDTO`, setting `time = dateTime.getEpochSecond()`
- `toChartDTO(Stock, List<Candle>)` — assembles the full `CandleChartDTO` including ticker and scalar SMA values

---

## Technical Decisions

| Decision | Rationale |
|---|---|
| `findCandlesByTicker` in port (not JPA-specific method) | Keeps domain port stable; infrastructure detail hidden |
| Epoch seconds for `time` | TradingView Lightweight Charts v4 requires this format natively |
| Scalar SMA values in `CandleChartDTO` | Server provides reference values; SMA line series computed client-side |
| `CandleDTOMapper` as `@Component` | Consistent with `StockDataDTOMapper` pattern; enables isolated unit testing |
| `BeanConfig` updated manually | `ManageAnalyzeStockService` is constructed manually via `@Bean`; new `CandleDTOMapper` parameter added |
